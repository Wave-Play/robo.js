Flashcore is the built-in persistent key-value database for Robo.js. It stores data that survives restarts, making it suitable for settings, records, and any information that needs long-term storage.

## Saving and Fetching Data

Flashcore works like [State](./state) but persists data permanently. All operations are asynchronous.

Here is an example that stores a user's high score:

<Tabs items={["TypeScript", "JavaScript"]} groupId="language" persist>
  <Tab value="TypeScript">
    ```ts title="src/commands/update-score.ts"
    import { Flashcore } from 'robo.js'
    import { createCommandConfig } from '@robojs/discordjs'
    import type { CommandInteraction } from 'discord.js'

    export const config = createCommandConfig({
    	options: [
    		{
    			name: 'score',
    			description: 'The new high score',
    			type: 'integer',
    			required: true
    		}
    	] as const
    })

    export default async (interaction: CommandInteraction) => {
    	const userId = interaction.user.id
    	const score = interaction.options.get('score')?.value as number

    	await Flashcore.set(userId, score)
    	return `New high score of ${score} saved.`
    }
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="src/commands/update-score.js"

    import { createCommandConfig } from '@robojs/discordjs'

    })

    	await Flashcore.set(userId, score)
    	return `New high score of ${score} saved.`
    }
    ```
  </Tab>
</Tabs>

And an example that retrieves it:

<Tabs items={["TypeScript", "JavaScript"]} groupId="language" persist>

**Note:** Always `await` Flashcore calls. They return promises because the underlying storage may be asynchronous.
</Callout>

## Data Types

Flashcore supports any serializable data type. Primitives and plain objects work, but functions and class instances do not.

<Tabs items={["TypeScript", "JavaScript"]} groupId="language" persist>
  <Tab value="TypeScript">
    ```ts
    await Flashcore.set('banned', true)
    await Flashcore.set('score', 40)
    await Flashcore.set('top-name', 'Robo')
    await Flashcore.set('top-user', {
    	name: 'Robo',
    	score: 40
    })

    await Flashcore.set('top-games', [
    	{ name: 'Robo', score: 40 },
    	{ name: 'Robo 2', score: 30 },
    	{ name: 'Robo 3', score: 20 }
    ])
    ```
  </Tab>
  <Tab value="JavaScript">

## Watching for Changes

The `on()` function lets you observe changes to a key's value:

<Tabs items={["TypeScript", "JavaScript"]} groupId="language" persist>
  <Tab value="TypeScript">
    ```ts title="src/commands/watch-score.ts"
    import { Flashcore } from 'robo.js'
    import type { CommandInteraction } from 'discord.js'

    export default async (interaction: CommandInteraction) => {
    	const userId = interaction.user.id

    	Flashcore.on(userId, (oldScore, newScore) => {
    		interaction.channel.send(`High score updated for ${userId}: ${newScore}`)
    	})

    	return `Watching for changes to ${userId}'s high score.`
    }
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="src/commands/watch-score.js"

    	})

    	return `Watching for changes to ${userId}'s high score.`
    ```
    ```js title="src/commands/stop-watching-score.js"
    }
    ```
  </Tab>
</Tabs>

## Namespaces

Namespaces prevent key collisions by categorizing data into separate groups. This is useful when managing data across multiple servers or contexts.

Pass a `namespace` property in the options object of any Flashcore function:

<Tabs items={["TypeScript", "JavaScript"]} groupId="language" persist>
  <Tab value="TypeScript">
    ```ts
    Flashcore.set('my-key', 'example-value', {
    	namespace: 'my-namespace'
    })
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js
    Flashcore.set('my-key', 'example-value', {
    	namespace: 'my-namespace'
    })
    ```
  </Tab>
</Tabs>

For example, to store per-server high scores, use the guild ID as the namespace:

<Tabs items={["TypeScript", "JavaScript"]} groupId="language" persist>
  <Tab value="TypeScript">
    ```ts title="src/commands/update-score.ts"
    import { Flashcore } from 'robo.js'
    import { createCommandConfig } from '@robojs/discordjs'
    import type { CommandInteraction } from 'discord.js'

    export const config = createCommandConfig({
    	options: [
    		{
    			name: 'score',
    			description: 'The new high score',
    			type: 'integer',
    			required: true
    		}
    	] as const
    })

    export default async (interaction: CommandInteraction) => {
    	const userId = interaction.user.id
    	const score = interaction.options.get('score')?.value as number

    	await Flashcore.set(userId, score, { // [!code highlight]
    		namespace: interaction.guildId // [!code highlight]
    	}) // [!code highlight]

    	return `New high score of ${score} saved.`
    }
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js title="src/commands/update-score.js"

    	]
    })
    ```

<Tabs items={["TypeScript", "JavaScript"]} groupId="language" persist>
  <Tab value="TypeScript">
    ```ts

    	namespace: interaction.guildId
    ```

Each namespace acts as an isolated group, so the same key in different namespaces stores independent values.

## Using Keyv Adapters

Flashcore uses the local filesystem by default but supports any Keyv adapter for external storage. For example, to use SQLite:

```typescript
// config/robo.mjs
import { SQLite } from '@keyv/sqlite'

export default {
	flashcore: {
		keyv: { // [!code highlight]
			store: new SQLite('sqlite://robo.db') // [!code highlight]
		} // [!code highlight]
	}
}
```

<Callout type="info">
**Note:** See the [Keyv documentation](https://github.com/jaredwray/keyv/tree/main#storage-adapters) for a full list of available storage adapters including Redis, PostgreSQL, MySQL, and MongoDB.
</Callout>

## TypeScript Support

Flashcore supports generics for type-safe retrieval:

<Tabs items={["TypeScript", "JavaScript"]} groupId="language" persist>
  <Tab value="TypeScript">
    ```ts
    const isBanned = await Flashcore.get<boolean>(userId + '-banned')
    const score = await Flashcore.get<number>(userId + '-score')
    const topName = await Flashcore.get<string>('top-name')

    interface Game {
    	name: string
    }

    interface UserSettings {
    	theme: string
    	notifications: boolean
    }

    const topGames = await Flashcore.get<Game[]>('top-games')
    const settings = await Flashcore.get<UserSettings>(userId + '-settings')
    ```
  </Tab>
  <Tab value="JavaScript">
    ```js
    const isBanned = await Flashcore.get(userId + '-banned')
    const score = await Flashcore.get(userId + '-score')
    const topName = await Flashcore.get('top-name')

    const topGames = await Flashcore.get('top-games')
    const settings = await Flashcore.get(userId + '-settings')
    ```
  </Tab>
</Tabs>

<Callout type="info">
**Note:** Generics only inform TypeScript of the expected return type. They do not parse or validate the stored data, so ensure you save data in the correct format.
</Callout>

## Flashcore vs. State

Use Flashcore when data needs to survive restarts or be stored externally. Use [State](./state) for fast, in-memory values that only need to last for the current session.

- **Persistence:** Flashcore stores data permanently. State clears on shutdown.
- **Operations:** Flashcore is asynchronous. State is synchronous.
- **External storage:** Flashcore supports Keyv adapters for databases like PostgreSQL. State is in-memory only.
- **Data types:** Flashcore requires serializable data. State can hold any JavaScript value, including class instances.

## Troubleshooting

### Data not persisting across restarts

Verify that you are using `Flashcore` and not `State`. State values clear on shutdown unless the `persist` option is set. Also ensure that the `/.robo/data` directory exists and is not being deleted by your deployment process.

### Namespace conflicts

If data from different contexts (e.g., different servers) is overlapping, make sure you are passing a unique `namespace` value to each Flashcore call. Using `interaction.guildId` as the namespace is a common pattern for per-server data.

### Keyv adapter errors

If you configured an external storage adapter and see connection errors, verify that the database is running and accessible. Check the connection string in your `config/robo.mjs` and ensure the adapter package is installed as a dependency.
