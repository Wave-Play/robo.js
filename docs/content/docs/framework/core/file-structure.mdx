The file structure is the foundation of every Robo.js project. Directories and file names determine your project's functionality, similar to frameworks like Next.js.

## Standard Structure

A standard Robo.js project contains the following directories:

<Files>
  <Folder name="/" defaultOpen disabled>
    <Folder name=".robo">
      <File name="(Generated files)" />
    </Folder>
    <Folder name="config">
      <File name="(Configuration files)" />
    </Folder>
    <Folder name="src">
      <File name="(Source code)" />
    </Folder>
    <File name=".env" />
    <File name="package.json" />
  </Folder>
</Files>

You will spend most of your time in the `/src` directory, where your project's features live. The `/config` directory holds project and plugin configurations.

Depending on your setup, you may have additional files from tools like ESLint or Prettier.

### Source Code

The `/src` directory is where your project's functionality is defined. Any file type supported by Node.js works here, including JavaScript, **[TypeScript](./typescript)**, and JSON. TypeScript works out of the box with no additional setup.

### Configuration

Config files live in the `/config` directory. These control project and plugin settings. Plugin config files are generated automatically when you run `npx robo add`.

You may rarely need to edit these files directly. See **[Configuration](./config)** for more details.

### Environment Variables

The `.env` file stores sensitive information such as API keys, database URLs, and Discord tokens. These variables are loaded into your project at startup.

See **[Environment Variables](./env-vars)** for more details.

### Package File

The `package.json` file is standard for Node.js projects. It contains metadata about your project including the name, version, dependencies, and scripts.

## Modules

For larger projects, modules let you group related functionality together. Each module is a self-contained unit within your project that follows the same file structure conventions.

See **[Modules](./modules)** for more details.

## .robo Directory

The `/.robo` directory is managed by Robo.js and contains generated files. You should not edit this directory manually, but the following sections explain what it contains.

### Build

`/.robo/build` contains compiled output from your project. TypeScript files are compiled to JavaScript here, and production bundles are stored in this location.

For plugins, this is the directory that gets published to npm.

### Data

`/.robo/data` contains **[Flashcore](./flashcore)** data. Flashcore uses the local filesystem by default but can be configured to use an external database.

<Callout type="warn">
**Warning:** Do not delete this directory or you may lose persisted data.
</Callout>

### Manifest

The `/.robo/manifest.json` file contains project metadata including the project name, version, registered plugins, and directory information. Robo.js generates and updates this file automatically for faster startup times.

### Temp Files

The `/.robo/temp` directory appears occasionally and holds temporary files generated during runtime, such as intermediate files created during compression.
